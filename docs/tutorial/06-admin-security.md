# 6. Protect the admin area

A login form alone does not secure an application. We will add authentication middleware, CSRF protection, validation and rate limiting.

## 6.1 Authentication middleware

Create an application middleware such as:

```text
app/Middleware/AdminAuth.php
```

Its job is simple: check whether the user is authenticated. If not, redirect to the login page.

Attach it only to admin routes:

```php
Router::group('/admin', ['AdminAuth']);
```

This keeps public pages free of unnecessary authentication work.

## 6.2 CSRF protection

For state-changing forms, use the CSRF middleware:

```php
Router::post('/admin/account', 'Admin\\UserController@update', ['Csrf']);
```

The form includes the CSRF token generated by the framework's helper.

Never disable CSRF protection simply to make a form easier to test.

## 6.3 Validate input

Validation belongs close to the application action. Check required fields, lengths and any business rules before writing to the database.

Do not assume browser validation is enough. Browser validation can be bypassed.

## 6.4 Rate-limit login

Use both an account-oriented bucket and a broader IP bucket where appropriate. This prevents a strict account limit from treating every user behind the same corporate NAT address as one person.

The configuration can contain:

```php
'rate_limit' => [
    'enabled' => true,
    'limit' => 60,
    'window' => 60,
    'routes' => [
        '/login' => [
            'account_field' => 'username',
            'account_limit' => 5,
            'account_window' => 300,
            'ip_limit' => 300,
            'ip_window' => 60,
        ],
    ],
],
```

For higher-risk public systems, consider a distributed rate-limit store or external anti-abuse service. File-backed limits are intentionally simple and suitable for small deployments.

## 6.5 Password changes

When an authenticated administrator changes a password:

1. require authentication
2. require a valid CSRF token
3. validate the new password
4. hash it with `password_hash()`
5. update the database
6. avoid returning the password or hash in a response

## 6.6 Admin CRUD

Your admin post controller can now implement:

```text
GET  /admin/posts
GET  /admin/posts/create
POST /admin/posts
GET  /admin/posts/{id}/edit
POST /admin/posts/{id}
POST /admin/posts/{id}/delete
```

Protect every state-changing route with CSRF and the whole group with authentication.
